# git-hygiene

作業を**完了扱いにする前**に使うSkill。重要資産を変更したのに、Git上の保全状態が未確定なままでは、まだ完了ではない。

`common-safe-implementation`（着手前の安全確認）・`common-code-review`（差分の品質検査）・`common-dev-log`（作業内容の記録）とは役割が異なる。このSkillは**Gitの保全状態だけ**を扱う。

## このSkillがやること

- 対象repo（および関連repo）のbranch・HEAD・追跡・ahead/behind・未追跡・未commit・未push・ignoreされた重要資産を確認する
- 残件を6分類（§3）のいずれかへ確定させる。「後で」「いつか整理」という宙ぶらりんの分類を許さない
- 安全条件を満たす差分だけをcommit・pushする
- 蓄積の兆候（§4）を完了報告で警告する

## このSkillがやらないこと

- `git add .`・無差別な一括stage
- 無関係な既存差分・由来不明の差分のcommit
- force push・rebase・reset・stash・branch削除/統合・`origin/HEAD`変更・remote新設・GitHub repo新設
- 秘密情報の内容をそのまま提示・commit
- 軽微な読み取り調査への過剰なcommit要求

## 1. 発動タイミング

次のいずれかで実施する：

- 実装バッチ完了時
- 正式設計書作成時・正式レビュー結果保存時
- 作業ログ・開発ログ作成時
- Project Kit・Skill・台帳・正本の更新時
- 重要ファイルを複数変更した時
- 別チャット・別セッションへ移動する前
- 別プロジェクト・別repoへ移動する前
- 作業中断時・その日の主要作業終了時
- ユーザーがGit回収・保全確認を依頼した時

ファイル変更を伴わない軽微な読み取り調査・単純な質問応答では発動しない。

## 2. 確認項目

対象repoについて、必要な範囲で確認する（無関係な全PC・全repo走査はしない。作業ディレクトリ・CLAUDE.md・AI_CONTEXT.md・Project Kitから自然に辿れる範囲に限定）：

```
git status（branch・working tree）
現在branch / HEAD
追跡branch / ahead・behind
未追跡ファイル
未commit差分（staged / unstaged）
未push commit
remoteの有無
Git ignoreされた重要資産（削除・追跡忘れではなく意図的な除外かを確認）
秘密情報混入の可能性
作業対象外ファイルの混在
別repoに残った関連差分（複数repoにまたがる作業の場合）
```

## 3. 残件の確定分類

残件は必ず次の6分類のいずれかへ確定させる。

### 3-1. 今回commit・pushする

条件（すべて満たす場合のみ）：今回作業の差分だけが明確／検収済み／無関係差分を巻き込まない／秘密情報なし／remote・追跡branchが正常／ユーザー指示または既存ルール上commit/pushしてよい。

### 3-2. commitするがpushできない

remoteがない、またはremote新設にユーザー判断が必要な場合。明記すること：commit hash／ローカルのみであること／外部バックアップされていないこと／次に必要な人間判断。

### 3-3. 意図的にGit管理外で保持する

ローカル専用設定・セッション情報・参考画像・機密情報・生成キャッシュ等。**`.gitignore`へ入れて終わりにしない。** 明記すること：保存場所／ignore理由／代替バックアップの有無／失われた場合の影響。

### 3-4. 次バッチへ明示的に引き継ぐ

未完成・未承認でcommitできない場合。明記すること：対象ファイル／未完理由／次に行う作業／いつ再判定するか／放置してよい期限または区切り。**「いつか整理」は禁止。**

### 3-5. 不要物として削除・除外する

既存の安全ルールとユーザー承認条件に従う。勝手に削除してはいけない資産は削除候補として報告するのみ。

### 3-6. 由来不明・混在により保留

由来不明の差分・複数作業が混ざったファイルは勝手にcommitしない。「今回スコープ外」で終わらせず明記すること：対象／推定由来／混在内容／分離可能性／次回の具体的な回収手順。

## 4. 蓄積の警告基準

以下に該当する場合、完了報告で警告する（正常に大量発生する生成物・依存関係ファイルまで件数だけで危険扱いしない）：

- 未追跡・変更ファイルが20件を超えた
- 複数の作業テーマが1ファイル・1repoに混在した
- 2回以上の作業バッチをまたいで同じ未commitが残った
- ローカルのみのcommitが増え続けている
- remoteなしのrepoに正式資産が追加された
- ignoreされた重要資産が新たに追加された
- 別repoに関連差分を残したまま主作業へ戻ろうとしている

## 5. commitの安全条件

次の場合は自動的・機械的にcommitしない：無関係な既存差分が混ざる／作業元が不明／ユーザー承認状態が不明／秘密情報の可能性がある／大量ファイルの一括stageが必要／複数テーマが1ファイル内で混在／main/master構造の操作が必要／rebase・reset・stash・force pushが必要／branch統合が必要。

今回作業の対象ファイルを明示的にstageすることを基本とする（`git add .`を標準手順にしない）。

## 6. pushの安全条件

次をすべて満たす場合のみpushする：remoteが設定済み／追跡branchが正しい／今回のcommitだけが対象／秘密情報なし／force push不要／branch構造に不明点なし／main/masterの整理を伴わない／ユーザーの指示または既存ルール上pushしてよい。

**[[AI-Workflow-System/01_harness/ChatGPT共同作業ルール正本]]の自動push条件（第4節、Vault・アプリ/プロダクトrepo問わず全repo共通）を満たす場合、個別確認なしでpushしてよい（2026-07-14・A-2.7、同日補正で全repo共通化）。** 通常のコードpushと本番公開・提出・配信・デプロイは別操作として扱い、後者は引き続きHuman-only。同正本の停止条件（第7節）に該当する場合はpushせず、理由・commit hash・未push件数・必要な人間判断を報告する。

禁止：force push・rebase・reset・stashによる差分隠蔽・branch削除/名称変更・main/master統合・`origin/HEAD`変更・remote新設・GitHub repo新設。これらが必要な場合は人間判断事項として止める。

## 7. 自己進化ループ設計との関係

このSkillは、[[AI-Workflow-System/01_harness/AI開発知識資産・自己進化ループ設計]]における「実装完了→検品→完了ログ→正式資産保全」の境界を安全に閉じるための補助Skillである。このSkill単独では、Project Kit/Skillの自動更新・正本の自動変更・自動化レベルL1以上の運用を開始しない。
